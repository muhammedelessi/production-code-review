# Contributing

Thanks for helping improve this skill.

## Review-quality rules

- Keep findings evidence-based and proportional to real production impact.
- Do not turn style preferences into Critical or High findings.
- Keep the initial review read-only; fixes require explicit approval.
- Prefer focused fixes over broad rewrites.
- Preserve clear separation between confirmed findings, hypotheses, and coverage gaps.
- Keep stack-specific detail in references rather than bloating `SKILL.md`.

## Pull requests

Explain the review problem being solved, include an example where possible, identify affected references, and state how the proposed behavior was validated.

## Versioning

Use semantic versioning. Breaking changes to severity semantics, report format, approval gates, or review contract require a major version bump.
